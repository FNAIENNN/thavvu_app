Summary

Updated after implementation pass:
- Persistent approval/request workflow base is now implemented through HodWorkflowStore.
- HOD approve/reject is persisted locally and writes audit logs.
- HOD site-based access controls are enforced in the workflow store.
- HOD dashboard now has Backend Workflow Monitor summary.

- Drawer/dashboard navigation now keeps HOD mode for modules.
- Daily Data, Attendance, Stock, Cash, Rental, and Food now open real HOD module review queues instead of static placeholders when isHOD is true.
- Tasks navigation now opens HODTasksScreen for HOD users.
- Remaining production limitation: this is still a local backend-compatible store using SharedPreferences, not a remote multi-device server. For real deployment, replace HodWorkflowStore with API/database implementation using the same models.

Original review summary:
The app already has an HOD/admin control panel concept, but many controls are currently local/demo UI state, not connected to a backend/database. HOD can monitor supervisor activity from dashboard cards, approve/reject demo requests, open modules, view sites/supervisors, set cash limits, add expense reasons, and access several HOD review screens. Some modules are only placeholders for HOD review.

Important problems / gaps found
-------------------------------

1. HOD dashboard is mostly static/demo data
Most lists like alerts, approval requests, supervisors, sites, balances are hardcoded in main_shell.dart. There is no backend/database/API connection.

2. Approval/reject does not really control module records
Approve/reject only changes _hodRequestStatuses in memory:
main_shell.dart:955-958

If app restarts, status is lost. It also does not update machine/attendance/cash/stock records.

3. Drawer navigation has a bug for HOD mode
In the drawer, some screens are opened as const without passing isHOD true:
main_shell.dart:1827-1834
main_shell.dart:1843-1861
main_shell.dart:1868-1871

Example:
Daily Data drawer opens const DailyDataScreen(), not DailyDataScreen(isHOD: _isHOD).
Attendance drawer opens const AttendanceScreen(), not AttendanceScreen(isHOD: _isHOD).

So if HOD opens modules from dashboard cards, HOD mode is passed correctly.
But if HOD opens modules from the side drawer, many modules open as supervisor/default mode.

4. Daily Data and Attendance HOD screens are placeholders
Daily:
daily_data_screen.dart:2599-2638

Attendance:
attendance_screen.dart:458-488

They display text but do not show actual pending items/actions.

5. Stock/Cash/Rental/Food have HOD flags or HOD text but not full HOD control
These modules need real role-based UI/actions if HOD must control supervisor actions.

6. No real supervisor monitoring history
HOD can see demo supervisors/sites/balances/alerts, but there is no persistent activity log like:
- who submitted what
- when submitted
- current status
- HOD approval history
- rejected reason
- supervisor correction/resubmission
- audit trail
